백엔드 API 스펙 (완전판)

중요 변경사항:
- 카카오페이의 "결제 준비(ready) → 승인(approve)" 2단계 플로우가 사라짐
- 토스페이먼츠는 클라이언트에서 직접 SDK로 결제 요청
- 백엔드는 결제 완료 후 승인(confirm) API만 제공
- 리다이렉트 URL은 백엔드가 아닌 프론트엔드에서 설정 (successUrl, failUrl)
- 실연동 모드(TOSS_PAY_ENABLE=true)와 테스트 모드(모킹) 지원

1. 결제 승인 API (POST /api/payments/toss/confirm)
   
   동작 방식:
   - 사용자가 토스 결제 완료 후 전달받은 paymentKey, orderId, amount를 JWT와 함께 전송
   - 서버는 주문 존재 여부, 주문자 일치, 결제 상태(PAID 아님), 상품 타입(TIME_CAPSULE), 금액 일치 검증
   - 실연동(TOSS_PAY_ENABLE=true)이면 TOSS_SECRET_KEY로 토스 v1/payments/confirm 호출
   - 테스트 모드에서는 모킹 응답 생성
   - 결제 완료 후 타임캡슐 생성
   
   요청:
   - Method: POST
   - URL: /api/payments/toss/confirm
   - Headers: { Authorization: "Bearer {JWT}" }
   - Body: {
       paymentKey: string,  // 1~200자
       orderId: string,     // 6~200자
       amount: number       // 결제 금액
     }
   
   응답 (201 Created):
   {
     order_id: string,
     payment_key: string,
     status: string,        // "PAID"
     amount: number,
     approved_at: string,   // ISO 8601 형식
     capsule_id: string,    // 생성된 타임캡슐 UUID
     receipt_url: string
   }
   
   에러 응답:
   - 400 AMOUNT_MISMATCH: 결제 금액이 주문 금액과 불일치
   - 400 ORDER_ALREADY_PAID: 이미 결제 완료된 주문
   - 400 TOSS_SECRET_KEY_REQUIRED: 실연동 모드인데 시크릿 키 없음
   - 400 TOSS_CONFIRM_FAILED: 토스 API 호출 실패 (토스 응답 메시지 포함)
   - 401 ORDER_NOT_OWNED: 다른 사용자의 주문
   - 401 Unauthorized: JWT 누락/만료
   - 404 ORDER_NOT_FOUND: 주문 정보 없음
   - 404 PRODUCT_NOT_FOUND_OR_INVALID: 상품이 TIME_CAPSULE이 아님

2. 결제 조회 API - paymentKey (GET /api/payments/toss/{paymentKey})
   
   동작 방식:
   - 내부 DB에서만 조회 (토스 API 호출 없음)
   - Payment 테이블에서 paymentKey로 검색
   - 취소 이력(payment_cancels) 함께 로드
   
   요청:
   - Method: GET
   - URL: /api/payments/toss/{paymentKey}
   - Headers: { Authorization: "Bearer {JWT}" }
   - Path Param: paymentKey (string)
   
   응답 (200 OK):
   {
     payment: {
       paymentKey: string,
       orderNo: string,
       tossStatus: string,        // "DONE", "CANCELED" 등
       method: string,             // "카드" 등
       currency: string,           // "KRW"
       amount: number,             // balance_amount (잔액)
       approvedAt: string,         // ISO 8601
       receiptUrl: string
     },
     cancels: [
       {
         transactionKey: string,
         cancelAmount: number,
         cancelReason: string,
         cancelStatus: string,
         canceledAt: string
       }
     ]
   }
   
   에러 응답:
   - 401 Unauthorized: JWT 누락/만료
   - 404 PAYMENT_NOT_FOUND: 결제 정보 없음

3. 결제 조회 API - orderNo (GET /api/payments/toss/orders/{orderNo})
   
   동작 방식:
   - 내부 DB에서만 조회 (토스 API 호출 없음)
   - Payment 테이블에서 orderNo로 검색
   - 취소 이력(payment_cancels) 함께 로드
   
   요청:
   - Method: GET
   - URL: /api/payments/toss/orders/{orderNo}
   - Headers: { Authorization: "Bearer {JWT}" }
   - Path Param: orderNo (string)
   
   응답 (200 OK):
   {
     payment: {
       paymentKey: string,
       orderNo: string,
       tossStatus: string,
       method: string,
       currency: string,
       amount: number,
       approvedAt: string,
       receiptUrl: string
     },
     cancels: [...]
   }
   
   에러 응답:
   - 401 Unauthorized: JWT 누락/만료
   - 404 PAYMENT_NOT_FOUND: 결제 정보 없음

4. 결제 취소 API (POST /api/payments/toss/{paymentKey}/cancel)
   
   동작 방식:
   - paymentKey로 결제 조회 후 주문 소유자 확인
   - 실연동(TOSS_PAY_ENABLE=true)이면 TOSS_SECRET_KEY로 토스 v1/payments/{paymentKey}/cancel 호출
   - 테스트 모드에서는 모킹 응답 생성
   - 부분 취소/전액 취소 모두 지원
   - 잔액이 0이거나 토스 응답 status가 CANCELED이면 내부 상태도 CANCELED로 변경
   - 취소 이력을 PaymentCancel 테이블에 저장 (중복 transactionKey는 저장 안 함)
   
   요청:
   - Method: POST
   - URL: /api/payments/toss/{paymentKey}/cancel
   - Headers: { Authorization: "Bearer {JWT}" }
   - Path Param: paymentKey (1~200자)
   - Body: {
       cancelReason: string,              // 필수, 1~200자
       cancelAmount?: number,             // 선택 (없으면 전액 취소)
       refundReceiveAccount?: {           // 선택 (가상계좌 환불용)
         bank: string,
         accountNumber: string,
         holderName: string
       }
     }
   
   응답 (200 OK):
   {
     payment_key: string,
     status: string,              // "CANCELED" 또는 "DONE" (부분 취소 시)
     balance_amount: number,      // 잔액
     cancels: [
       {
         transactionKey: string,
         cancelAmount: number,
         cancelReason: string,
         cancelStatus: string,
         canceledAt: string
       }
     ],
     receipt_url: string
   }
   
   에러 응답:
   - 400 TOSS_SECRET_KEY_REQUIRED: 실연동 모드인데 시크릿 키 없음
   - 400 TOSS_CANCEL_FAILED: 토스 API 호출 실패 (토스 응답 메시지 포함)
   - 401 ORDER_NOT_OWNED: 다른 사용자의 결제
   - 401 Unauthorized: JWT 누락/만료
   - 404 PAYMENT_NOT_FOUND: 결제 정보 없음

환경 변수 설정:
- TOSS_PAY_ENABLE: "true"이면 실연동, 그 외는 테스트 모드(모킹)
- TOSS_SECRET_KEY: 실연동 시 필수 (Basic 인증용)
- TOSS_BASE_URL: 기본값 https://api.tosspayments.com (선택사항)

[기존 - 카카오페이]

4. 사용자: 결제 완료 → pg_token과 함께 앱으로 복귀
5. 프론트 → 백엔드: POST /api/payments/kakao/approve (결제 승인)

[변경 - 토스페이먼츠]
1. 프론트: Toss Payments SDK 초기화 (클라이언트 키 사용)
2. 프론트: SDK.requestPayment() 호출 → 토스 결제 페이지 표시
3. 사용자: 결제 완료 → paymentKey, orderId, amount와 함께 앱으로 복귀 (successUrl)
4. 프론트 → 백엔드: POST /api/payments/toss/confirm (결제 승인)
5. 백엔드: 토스 API로 승인 처리 후 결제 정보 저장
6. (선택) 프론트 → 백엔드: GET /api/payments/toss/{paymentKey} (결제 조회)

유저 시나리오

1) 결제하기 버튼 클릭
   1. 사용자가 모든 약관에 동의하고 "토스페이먼츠로 결제하기" 버튼 클릭
   2. 로딩 상태 표시 시작
   3. Toss Payments SDK 호출
      - orderId: orderData.order_id
      - amount: orderSummary.totalPrice
      - orderName: "타임캡슐 생성"
      - customerName: formData에서 가져오기 (또는 "고객")
     - successUrl: "timeegg://pay/toss/success"
     - failUrl: "timeegg://pay/toss/fail"
   4. SDK가 토스페이먼츠 결제 페이지 표시
   5. 사용자가 결제 완료하면 successUrl로 리다이렉트
      - URL 파라미터: paymentKey, orderId, amount
   6. 실패 시:
      - 에러 메시지 표시 (Alert)
      - 로딩 상태 종료

2) 토스페이먼츠 결제 완료 후 복귀 (successUrl)
   1. 사용자가 토스페이먼츠 결제를 완료하면 앱으로 복귀
   2. URL에서 paymentKey, orderId, amount 파라미터 추출
   3. POST /api/payments/toss/confirm API 호출
      - paymentKey, orderId, amount 전달
   4. 성공 시:
      - 결제 완료 모달 표시 (ConfirmModal - PAYMENT_COMPLETE)
      - 부모 컴포넌트로 결제 성공 이벤트 전달 (onPaymentSuccess 콜백)
      - 타임캡슐 생성 완료 화면으로 이동
   5. 실패 시:
      - 에러 메시지 표시 (Alert)
      - 결제 화면으로 복귀

3) 결제 취소/실패 (failUrl)
   1. 사용자가 토스페이먼츠 결제를 취소하거나 실패하면 앱으로 복귀
   2. URL에서 code, message 파라미터 추출
   3. 에러 메시지 표시 (Alert)
   4. 결제 화면 유지 (재시도 가능)

에러 처리

1) 네트워크 에러 (status === 0)
   - "네트워크 연결을 확인해주세요" 메시지 표시
   - 재시도 가능 상태 유지

2) 400 에러 (잘못된 요청)
   결제 승인 API:
   - AMOUNT_MISMATCH: "결제 금액이 일치하지 않습니다"
   - ORDER_ALREADY_PAID: "이미 결제가 완료된 주문입니다"
   - TOSS_SECRET_KEY_REQUIRED: "결제 시스템 설정 오류입니다. 관리자에게 문의해주세요"
   - TOSS_CONFIRM_FAILED: "결제 승인에 실패했습니다: {토스 응답 메시지}"
   
   결제 취소 API:
   - TOSS_SECRET_KEY_REQUIRED: "결제 시스템 설정 오류입니다. 관리자에게 문의해주세요"
   - TOSS_CANCEL_FAILED: "결제 취소에 실패했습니다: {토스 응답 메시지}"
   
   기타: 백엔드 메시지 그대로 표시

3) 401 에러 (인증 오류)
   - ORDER_NOT_OWNED: "다른 사용자의 주문/결제입니다"
   - Unauthorized (JWT 누락/만료): "로그인이 필요합니다"
   - 로그인 화면으로 이동 (선택사항)

4) 404 에러 (리소스 미존재)
   결제 승인 API:
   - ORDER_NOT_FOUND: "주문 정보를 찾을 수 없습니다"
   - PRODUCT_NOT_FOUND_OR_INVALID: "상품 정보가 유효하지 않습니다"
   
   결제 조회/취소 API:
   - PAYMENT_NOT_FOUND: "결제 정보를 찾을 수 없습니다"
   
   이전 화면으로 이동 (선택사항)

5) 500 에러 (서버 오류)
   - "일시적인 오류가 발생했습니다. 잠시 후 다시 시도해주세요"

주의사항:
- TOSS_SECRET_KEY_REQUIRED, TOSS_CONFIRM_FAILED, TOSS_CANCEL_FAILED는 400 에러로 반환됨 (500 아님)
- 에러 코드는 response.data.code에 포함됨
- 토스 API 실패 시 토스의 응답 메시지도 함께 표시

         if (errorCode === 'AMOUNT_MISMATCH') {

         } else {
           message = error.response?.data?.message || message;
         }
       } else if (status === 401) {
         message = '로그인이 필요합니다';
       } else if (status === 404) {

         if (errorCode === 'ORDER_NOT_FOUND') {
           message = '주문 정보를 찾을 수 없습니다';
         } else if (errorCode === 'PRODUCT_NOT_FOUND_OR_INVALID') {
           message = '상품 정보가 유효하지 않습니다';
         }
       } else if (status === 500) {

         message = '네트워크 연결을 확인해주세요';
       }
       
       const paymentError: PaymentError = { status, message };
       throw paymentError;
     }
   };

참고사항

1) 백엔드 API 차이점
   - 카카오페이: ready → redirect → approve (3단계)
   - 토스페이먼츠: SDK 호출 → successUrl 리다이렉트 → confirm (2단계)
   - 토스페이먼츠는 결제 준비 API(/ready)가 없으며, SDK가 직접 토스 서버와 통신
   - 프론트엔드는 결제 완료 후 /confirm API만 호출

2) 리다이렉트 URL 관리
   - 카카오페이: 백엔드가 redirect_url 반환
   - 토스페이먼츠: 프론트엔드가 successUrl/failUrl 설정
  - 딥링크 사용: timeegg://pay/toss/success

3) 파라미터 차이
   - 카카오페이: pg_token (승인용 토큰)
   - 토스페이먼츠: paymentKey, orderId, amount (3개 파라미터)

4) 토스페이먼츠 공식 문서
   - https://docs.tosspayments.com/
   - React Native 연동 가이드 참고

5) 딥링크 처리
  - 성공: timeegg://pay/toss/success?paymentKey={key}&orderId={id}&amount={amount}
  - 실패: timeegg://pay/toss/fail?code={code}&message={message}
