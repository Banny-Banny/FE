백엔드 API 스펙

1. 토스 결제 단건 조회 (paymentKey) - GET /api/payments/toss/{paymentKey}

   동작 방식:
   - 클라이언트가 결제키 paymentKey를 경로 파라미터로, JWT를 헤더로 담아 요청
   - 서버는 Payment 테이블에서 paymentKey로 결제 정보를 찾음
   - 취소 이력(payment_cancels)을 함께 로드하여 반환
   - 결제가 없으면 404(PAYMENT_NOT_FOUND) 반환

   요청:
   - Method: GET
   - URL: /api/payments/toss/{paymentKey}
   - Headers: { Authorization: "Bearer {JWT}" }
   - Path Param: paymentKey (string)

   응답 (200 OK):
   {
     payment: {
       paymentKey: string,
       orderNo: string,
       tossStatus: string,        // "DONE", "CANCELED" 등
       method: string,             // "카드" 등
       currency: string,           // "KRW"
       amount: number,             // balance_amount (잔액)
       approvedAt: string,         // ISO 8601
       receiptUrl: string
     },
     cancels: [
       {
         transactionKey: string,
         cancelAmount: number,
         cancelReason: string,
         cancelStatus: string,
         canceledAt: string
       }
     ]
   }

   에러 응답:
   - 401: JWT 누락/만료
   - 404 PAYMENT_NOT_FOUND: 결제 정보를 찾을 수 없음

2. 토스 결제 단건 조회 (orderNo) - GET /api/payments/toss/orders/{orderNo}

   동작 방식:
   - 클라이언트가 주문번호 orderNo를 경로 파라미터로, JWT를 헤더로 담아 요청
   - 서버는 Payment 테이블에서 orderNo로 결제 정보를 찾음
   - 취소 이력(payment_cancels)을 함께 로드하여 반환
   - 결제가 없으면 404(PAYMENT_NOT_FOUND) 반환

   요청:
   - Method: GET
   - URL: /api/payments/toss/orders/{orderNo}
   - Headers: { Authorization: "Bearer {JWT}" }
   - Path Param: orderNo (string)

   응답 (200 OK):
   {
     payment: {
       paymentKey: string,
       orderNo: string,
       tossStatus: string,        // "DONE", "CANCELED" 등
       method: string,             // "카드" 등
       currency: string,           // "KRW"
       amount: number,             // balance_amount (잔액)
       approvedAt: string,         // ISO 8601
       receiptUrl: string
     },
     cancels: [
       {
         transactionKey: string,
         cancelAmount: number,
         cancelReason: string,
         cancelStatus: string,
         canceledAt: string
       }
     ]
   }

   에러 응답:
   - 401: JWT 누락/만료
   - 404 PAYMENT_NOT_FOUND: 주문 번호에 해당하는 결제를 찾을 수 없음

중요:
- 이 API들은 내부 DB에서만 조회 (토스 API 호출 없음)
- 데이터 소스: Payment 테이블 + payment_cancels 관계
- 인증: JwtAuthGuard (Bearer JWT)
- 기존 components/toss-payments/api/payment.ts에 getTossPaymentByKey, getTossPaymentByOrderNo 함수가 이미 구현되어 있음

주의사항

1. 엔드포인트 선택
   - getTossPaymentByOrderNo 사용 권장 (주문번호 기반)
   - 사용자가 주문번호를 더 쉽게 기억하고 확인 가능
   - 결제키는 내부적으로만 사용

2. 결제 내역 목록 API 부재
   - 현재 제공된 API는 단건 조회만 가능
   - 여러 건의 결제 내역을 조회하려면:
     * 옵션 1: 백엔드에 결제 내역 목록 조회 API 추가 요청 (권장)
       예: GET /api/payments/toss/my-payments?page=1&limit=10
     * 옵션 2: 현재는 단건 조회 기능만 구현 (주문번호 입력받아 조회)
   - 이 프롬프트에서는 옵션 1을 가정하고 구현하되, 목록 API가 없으면 옵션 2로 대체
   - 구조는 향후 목록 API 추가 시 쉽게 확장 가능하도록 설계

3. 데이터 흐름
   - (목록 API 있는 경우)
     * 컴포넌트 마운트 → 결제 내역 목록 조회
     * 목록에서 항목 클릭 → 상세 정보 BottomSheet 표시
   - (목록 API 없는 경우)
     * 주문번호 입력 필드 제공
     * 주문번호 입력 → 검색 버튼 클릭 → 결제 정보 조회
     * 결제 정보를 카드 형태로 표시
