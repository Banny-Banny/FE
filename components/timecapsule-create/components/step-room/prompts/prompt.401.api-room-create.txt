API응답명세) 백엔드 응답 구조

대기실 생성 API
엔드포인트: POST /api/capsules/step-rooms/create
인증: Bearer {JWT_TOKEN} (필수)
Content-Type: application/json

요청 Body:
{
  "order_id": "실제 결제 완료 후 받은 orderId (UUID)"
}

예시:
{
  "order_id": "77fd8584-7877-4b70-a720-b7042a355125"
}

성공 응답 (200 OK 또는 201 Created):
{
  "capsule_id": "3dc6c7ee-f26f-41b7-aee3-1daaac34a46e",
  "created_at": "2026-01-05T08:27:08.313Z",
  "current_participants": 1,
  "deadline": "2026-01-06T08:27:08.324Z",
  "invite_code": "5ZJDD8",
  "max_participants": 2,
  "open_date": "2026-01-12T08:27:08.324Z",
  "status": "WAITING",
  "title": "나의 타임캡슐"
}

에러 응답:
- 400 Bad Request: 잘못된 order_id 형식
- 401 Unauthorized: JWT 토큰 없음 또는 유효하지 않음
- 404 Not Found: 존재하지 않는 order_id
- 500 Internal Server Error: 서버 내부 오류

주의:
- 응답 구조는 CreateRoomResponse 타입 (snake_case)
- 대기실이 이미 존재하는 경우에도 동일한 응답 반환 (idempotent)
- capsule_id는 추후 참여자 조회 및 설정값 조회에 사용됨

응답필드설명) 각 필드의 의미 및 활용

1. capsule_id (string, UUID)
   - 캡슐(대기실) 고유 ID
   - 추후 참여자 API 호출 시 사용 (GET /api/capsules/step-rooms/:capsuleId)
   - 설정값 조회 API 호출 시 사용 (GET /api/capsules/step-rooms/:capsuleId/settings)

2. title (string)
   - 방장이 설정한 캡슐 이름 (orders에서 설정한 제목)
   - 주의: getRoomSettings의 capsule_name이 더 정확할 수 있음

3. open_date (string, ISO 8601)
   - 캡슐 개봉 날짜
   - 예: "2026-01-12T08:27:08.324Z"
   - UI 표시 시 YYYY-MM-DD 형식으로 변환 필요

4. max_participants (number)
   - 총 참여 가능 인원 수
   - 참여자 슬롯 개수 결정

5. current_participants (number)
   - 현재 참여 중인 인원수
   - UI에 "현재 인원/최대 인원" 형태로 표시

6. deadline (string, ISO 8601)
   - 작성 마감 시한
   - 예: "2026-01-06T08:27:08.324Z"
   - UI에 남은 시간 계산하여 표시

7. invite_code (string)
   - 초대 코드 (6자리 영숫자)
   - 예: "5ZJDD8"
   - 공유 기능에서 사용

8. status (string)
   - 대기실 상태
   - 값: "WAITING" | "COMPLETED" | "EXPIRED"
   - UI 상태 표시에 사용

9. created_at (string, ISO 8601)
   - 대기실 생성 시간
   - 로깅 및 디버깅용

구현가이드-1) API 호출 함수 작성

파일: components/timecapsule-create/components/step-room/api/capsule.ts

목적:

기능:
1. createRoomAndGetSettings(orderId: string): Promise<CreateRoomResponse>
   - POST /api/capsules/step-rooms/create 호출
   - Body: { "order_id": orderId }
   - Authorization: Bearer {token} 헤더 포함 (apiClient가 자동 처리)
   - 응답을 그대로 반환 (snake_case 유지)
   - 에러 처리 및 예외 던지기

구현 예시:
```typescript
import { apiClient } from '@/utils/apiClient';
import type { CreateRoomRequest, CreateRoomResponse } from '../types';

/**
 * 대기실 생성 API
 * @param orderId 주문 ID (UUID)
 * @returns 대기실 생성 응답 (snake_case)
 * @throws 400: 잘못된 order_id 형식
 * @throws 401: JWT 토큰 없음 또는 유효하지 않음
 * @throws 404: 존재하지 않는 order_id
 * @throws 500: 서버 내부 오류
 */
export async function createRoomAndGetSettings(
  orderId: string
): Promise<CreateRoomResponse> {
  try {
    console.log('🔄 [API] 대기실 생성 시작 - orderId:', orderId);

    // apiClient는 자동으로 JWT 토큰을 헤더에 포함시킴
    const response = await apiClient.post<CreateRoomResponse, CreateRoomRequest>(
      '/api/capsules/step-rooms/create',
      {
        order_id: orderId,
      }
    );

    console.log('✅ [API] 대기실 생성 성공:', response.data);
    return response.data;
  } catch (error: any) {
    if (error.response?.status === 400) {
      console.error('❌ [API] 잘못된 order_id 형식 (400)');
      throw new Error('잘못된 주문 ID 형식입니다.');
    }
    if (error.response?.status === 401) {
      console.error('❌ [API] 인증 실패 (401)');
      throw new Error('인증이 필요합니다. 로그인 후 다시 시도해주세요.');
    }
    if (error.response?.status === 404) {
      console.error('❌ [API] 존재하지 않는 order_id (404)');
      throw new Error('주문 정보를 찾을 수 없습니다.');
    }
    if (error.response?.status === 500) {
      console.error('❌ [API] 서버 내부 오류 (500)');
      throw new Error('일시적인 오류가 발생했습니다. 잠시 후 다시 시도해주세요.');
    }
    console.error('❌ [API] 대기실 생성 실패:', error.message);
    throw new Error(`API 호출 실패: ${error.response?.status || 'Network Error'}`);
  }
}
```

import { useState, useEffect } from 'react';
import { createRoomAndGetSettings, getRoomSettings } from '../api/capsule';
import type { CreateRoomResponse, RoomSettingsResponse } from '../types';
import { mockRoomData } from '../constants';

export function useRoomData(orderId?: string) {
  const [roomSettings, setRoomSettings] = useState<RoomSettingsResponse | null>(null);
  const [createRoomResponse, setCreateRoomResponse] = useState<CreateRoomResponse | null>(null);
  const [capsuleId, setCapsuleId] = useState<string | null>(null);
  const [isLoading, setIsLoading] = useState(true);
  const [error, setError] = useState<Error | null>(null);

  useEffect(() => {
    async function loadRoomData() {
      setIsLoading(true);
      setError(null);

      try {
        if (orderId) {
          // ⭐ 1단계: 대기실 생성
          console.log('🔄 [useRoomData] 대기실 생성 시작 - orderId:', orderId);
          const roomData = await createRoomAndGetSettings(orderId);

          // 실제 API 응답 저장
          setCreateRoomResponse(roomData);
          const extractedCapsuleId = roomData.capsule_id;
          setCapsuleId(extractedCapsuleId);

          console.log('✅ [useRoomData] 대기실 생성 성공, capsuleId:', extractedCapsuleId);

          // ⭐ 2단계: 대기실 설정값 조회 (max_images_per_person, has_music, has_video 포함)
          try {
            console.log('🔄 [useRoomData] 대기실 설정값 조회 시작 - capsuleId:', extractedCapsuleId);
            const settingsData = await getRoomSettings(extractedCapsuleId);

            // CreateRoomResponse의 추가 정보와 병합
            // getRoomSettings의 capsule_name이 orders에서 설정한 정확한 제목이므로 우선 사용
            const mergedSettings: RoomSettingsResponse = {
              ...settingsData,
              room_id: roomData.capsule_id,
              // capsule_name은 getRoomSettings에서 가져온 값 사용 (orders에서 설정한 제목)
              open_date: roomData.open_date.split('T')[0], // ISO 8601에서 YYYY-MM-DD 추출
              max_participants: roomData.max_participants,
            };
            setRoomSettings(mergedSettings);

            console.log('✅ [useRoomData] 대기실 설정값 조회 성공:', mergedSettings);
          } catch (settingsError) {
            console.warn('⚠️ [useRoomData] 설정값 조회 실패, 기본값 사용:', settingsError);
            // 설정값 조회 실패 시 CreateRoomResponse만으로 구성
            const fallbackSettings: RoomSettingsResponse = {
              room_id: roomData.capsule_id,
              capsule_name: roomData.title, // fallback: CreateRoomResponse의 title 사용
              open_date: roomData.open_date.split('T')[0],
              max_participants: roomData.max_participants,
              max_images_per_person: 3, // 기본값
              has_music: false, // 기본값
              has_video: false, // 기본값
            };
            setRoomSettings(fallbackSettings);
          }
        } else {
          // orderId가 없으면 목데이터 사용
          console.log('ℹ️ [useRoomData] orderId 없음, 목데이터 사용');
          await new Promise((resolve) => setTimeout(resolve, 300)); // 로딩 시뮬레이션
          setRoomSettings(mockRoomData);
          setCapsuleId(mockRoomData.room_id);
        }
      } catch (err) {
        console.warn('⚠️ [useRoomData] API 호출 실패, 목데이터 사용:', err);
        setError(err instanceof Error ? err : new Error('API 호출 실패'));
        // 목데이터로 폴백 (snake_case)
        setRoomSettings(mockRoomData);
        setCapsuleId(mockRoomData.room_id);
      } finally {
        setIsLoading(false);
      }
    }

    loadRoomData();
  }, [orderId]);

  return {
    roomSettings,
    createRoomResponse,
    capsuleId,
    isLoading,
    error,
    calculateProgress,
    canSubmit,
  };
}

활용시나리오) 결제 완료 후 대기실 진입 플로우

1. 사용자가 결제 완료
   - 토스페이먼츠 결제 완료 후 orderData.order_id 수신
   - 결제 완료 모달에서 대기실 페이지로 이동 시 orderId 전달
   - 예: orderData.order_id = "77fd8584-7877-4b70-a720-b7042a355125"

2. 대기실 페이지 진입
   - orderId를 URL 파라미터에서 추출
   - useRoomData(orderId) 호출

3. ⭐ 1단계: 대기실 생성
   - POST /api/capsules/step-rooms/create 호출
   - Body: { "order_id": orderId }
   - Authorization: Bearer {JWT_TOKEN} 헤더 포함
   - 응답 데이터 수신 (capsule_id, title, deadline, invite_code 등)
   - capsule_id 추출

4. ⭐ 2단계: 대기실 설정값 조회
   - GET /api/capsules/step-rooms/:capsuleId/settings 호출
   - max_images_per_person, has_music, has_video 정보 수신

5. UI 동적 구성
   - 정보 카드: 캡슐 이름, 개봉일, 참여자 수 표시
   - 마감 시간: deadline 기반 남은 시간 계산
   - 초대 코드: invite_code를 공유 기능에 사용

에러처리가이드) 에러별 대응 전략

1. 400 Bad Request (잘못된 order_id 형식)
   - 원인: 잘못된 UUID 형식, 빈 문자열
   - 대응: 목데이터 폴백 + 에러 토스트
   - 메시지: "잘못된 주문 ID 형식입니다."

2. 401 Unauthorized (JWT 토큰 없음 또는 유효하지 않음)
   - 원인: 로그인하지 않음, 토큰 만료
   - 대응: 목데이터 폴백 + 로그인 페이지로 리다이렉트 (선택사항)
   - 메시지: "인증이 필요합니다. 로그인 후 다시 시도해주세요."

3. 404 Not Found (존재하지 않는 orderId)
   - 원인: 잘못된 orderId, 삭제된 주문
   - 대응: 목데이터 폴백 + 에러 토스트
   - 메시지: "주문 정보를 찾을 수 없습니다."

4. 500 Internal Server Error
   - 원인: 서버 장애, DB 오류
   - 대응: 목데이터 폴백 + 재시도 버튼 (선택사항)
   - 메시지: "일시적인 오류가 발생했습니다."

5. Network Error
   - 원인: 인터넷 연결 끊김, 서버 다운
   - 대응: 목데이터 폴백 + 재시도 버튼
   - 메시지: "네트워크 연결을 확인해주세요."

에러 처리 우선순위:
1. 목데이터로 폴백 (앱 사용 가능하도록)
2. 콘솔 로그로 에러 기록 (개발자 디버깅용)
3. 사용자 피드백 제공 (토스트, 모달 등) (선택사항)
4. 재시도 기능 제공 (선택사항)

주의사항)

1. API 응답 형식 준수
   - 백엔드가 snake_case로 응답
   - 프론트엔드는 snake_case를 그대로 사용 (프로젝트 일관성)
   - 타입 불일치 방지

2. 목데이터 폴백 전략
   - API 호출 실패 시 앱이 멈추지 않도록
   - 개발 환경에서도 정상 작동
   - 프로덕션에서는 에러 로깅 필수

3. 기존 로직 유지
   - UI/스타일 수정 금지
   - 기존 목데이터 로직은 폴백으로 활용
   - Props, useState 등 기존 구조 유지

4. TypeScript 타입 안정성
   - API 응답 타입 명시 (CreateRoomResponse, snake_case)
   - any 사용 금지

5. 에러 처리
   - try-catch 블록 필수
   - 에러 로깅 (console.error)
   - 사용자 피드백 (선택사항)

6. ⭐ 인증 필수
   - Bearer {JWT_TOKEN} 헤더 필수
   - apiClient가 자동으로 토큰을 헤더에 포함시킴
   - 401 에러 시 로그인 페이지로 리다이렉트 고려

7. ⭐ 2단계 API 호출
   - 1단계: 대기실 생성 (createRoomAndGetSettings)
   - 2단계: 설정값 조회 (getRoomSettings) - 별도 프롬프트 참고
   - capsule_id를 1단계에서 추출하여 2단계에 사용

8. ⭐ orderId 출처 및 우선순위
   - 실제 사용: 결제 완료 후 받은 orderId 사용 (orderData.order_id)
     - 토스페이먼츠 결제 완료 후 orderData.order_id 전달
     - 결제 완료 모달에서 대기실 페이지로 이동 시 Props 또는 URL 파라미터로 전달
   - 테스트용 (개발 환경에서만):
     - 테스트용 orderId: '77fd8584-7877-4b70-a720-b7042a355125' (하드코딩)
     - orderId가 없을 때만 폴백으로 사용
   - ⭐ orderId 우선순위: Props > URL 파라미터 > 하드코딩된 테스트 ID (폴백용)
   - 프로덕션에서는 반드시 Props나 URL 파라미터로 전달 (결제 완료 후 받은 orderId)
